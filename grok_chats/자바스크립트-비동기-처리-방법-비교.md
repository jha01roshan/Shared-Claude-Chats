## Assistant

자바스크립트에서 비동기 처리를 다루는 주요 방법은 크게 세 가지로 나눌 수 있습니다: **콜백(callback)**, **Promise**, 그리고 **async/await**입니다. 이 세 가지 방법을 모두 설명하고, 특징을 비교하며, 간단한 예제를 제공하겠습니다. 또한 이들을 섞어서 사용하는 가능성과 적합한 사용 시점에 대해서도 다루겠습니다.

---

### 1. 콜백 (Callback)
#### 설명
콜백은 비동기 작업이 완료되었을 때 실행할 함수를 인자로 전달하는 방식입니다. 자바스크립트에서 비동기 처리의 전통적인 방법으로, 초창기에 많이 사용되었습니다.

#### 특징
- **장점**: 간단한 비동기 작업에서 직관적이고 가볍게 사용할 수 있음.
- **단점**: 중첩된 비동기 호출이 많아지면 "콜백 지옥(callback hell)"이라 불리는 가독성 저하와 유지보수 어려움이 발생함.
- **에러 처리**: try-catch로 직접 잡기 어려움. 에러를 콜백 함수에 인자로 전달해 처리해야 함.

#### 예제
```javascript
function fetchData(callback) {
  setTimeout(() => {
    callback("데이터 가져옴");
  }, 1000);
}

fetchData((result) => {
  console.log(result); // 1초 후 "데이터 가져옴" 출력
});
```

---

### 2. Promise
#### 설명
Promise는 비동기 작업의 성공(resolve) 또는 실패(reject)를 약속(promise) 형태로 다루는 객체입니다. ES6에서 도입되었으며, 콜백 지옥 문제를 해결하기 위해 등장했습니다.

#### 특징
- **장점**: 체이닝(`.then`, `.catch`)을 통해 비동기 작업을 순차적으로 관리 가능. 에러 처리가 명확함.
- **단점**: 여전히 코드가 길어질 수 있고, 복잡한 로직에서는 가독성이 떨어질 수 있음.
- **에러 처리**: `.catch`로 실패 시 에러를 쉽게 핸들링 가능.

#### 예제
```javascript
function fetchData() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve("데이터 가져옴");
    }, 1000);
  });
}

fetchData()
  .then((result) => console.log(result)) // 1초 후 "데이터 가져옴" 출력
  .catch((error) => console.error(error));
```

---

### 3. async/await
#### 설명
async/await는 Promise를 기반으로 한 문법糖(syntactic sugar)으로, ES8에서 도입되었습니다. 비동기 코드를 동기 코드처럼 작성할 수 있게 해줍니다.

#### 특징
- **장점**: 가독성이 뛰어나고, 동기 코드처럼 직관적임. try-catch로 에러 처리가 쉬움.
- **단점**: 함수가 반드시 `async`로 선언되어야 하며, 병렬 처리를 위해 추가 작업(`Promise.all`)이 필요할 수 있음.
- **에러 처리**: try-catch 블록으로 자연스럽게 처리 가능.

#### 예제
```javascript
async function fetchData() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve("데이터 가져옴");
    }, 1000);
  });
}

async function run() {
  try {
    const result = await fetchData();
    console.log(result); // 1초 후 "데이터 가져옴" 출력
  } catch (error) {
    console.error(error);
  }
}

run();
```

### 특징 비교
| 방식         | 가독성       | 에러 처리         | 복잡한 비동기 흐름 | 사용 난이도 |
|--------------|--------------|-------------------|-------------------|-------------|
| **콜백**     | 낮음         | 콜백 내 처리      | 콜백 지옥 발생    | 쉬움        |
| **Promise**  | 중간         | `.catch` 사용     | 체이닝으로 해결   | 중간        |
| **async/await** | 높음       | try-catch 사용    | 동기식처럼 관리   | 쉬움(익숙해지면) |

---

### 섞어서 사용할 수 있는가?
네, 이 세 가지 방법을 섞어서 사용할 수 있습니다. 실제로 실무에서는 상황에 따라 섞이는 경우가 많습니다. 예를 들어:
- **콜백과 Promise**: 일부 오래된 API는 콜백 기반이므로, 이를 Promise로 감싸서 사용(`Promise.promisify` 활용).
- **Promise와 async/await**: Promise를 반환하는 함수를 `await`로 호출 가능.
- **모두 함께**: 복잡한 프로젝트에서는 세 가지가 혼합될 수 있음.

#### 섞은 예제
```javascript
// 콜백 기반 함수
function fetchWithCallback(callback) {
  setTimeout(() => callback("콜백 데이터"), 1000);
}

// Promise로 변환
function fetchPromise() {
  return new Promise((resolve) => {
    fetchWithCallback((data) => resolve(data));
  });
}

// async/await로 사용
async function runMixed() {
  try {
    const result = await fetchPromise();
    console.log(result); // 1초 후 "콜백 데이터" 출력
  } catch (error) {
    console.error(error);
  }
}

runMixed();
```

### 언제 무엇을 사용하는 것이 유리한가?
1. **콜백**
   - 간단한 단일 비동기 작업(예: 타이머, 이벤트 리스너).
   - 오래된 코드나 라이브러리와 호환성 유지 필요 시.

2. **Promise**
   - 여러 비동기 작업을 체이닝하거나 순차적으로 실행할 때.
   - 병렬 처리가 필요할 때(`Promise.all` 활용).
   - 중간 복잡도의 프로젝트에서 가독성과 유지보수성을 높이고 싶을 때.

3. **async/await**
   - 복잡한 비동기 흐름을 동기 코드처럼 관리하고 싶을 때.
   - 에러 처리를 간단히 하고, 코드 가독성을 극대화하고 싶을 때.
   - 최신 프로젝트에서 표준으로 사용.

#### 상황별 추천
- **작고 단순한 작업**: 콜백.
- **중간 규모, 순차적 작업**: Promise.
- **복잡한 흐름, 현대적인 코드**: async/await.

### 결론
- 세 가지 방법 모두 유효하며, 프로젝트 요구사항과 코드 스타일에 따라 선택하면 됩니다.
- 현대 자바스크립트에서는 **async/await**가 가장 권장되지만, Promise를 이해하는 것이 중요합니다(내부적으로 Promise 기반이기 때문).
- 섞어서 사용할 때는 코드 일관성을 유지하고, 팀원과의 협업을 고려해 가독성을 우선시하세요.
